Adaptive Sort Benchmarking — Deterministic vs Randomized QuickSort

Deterministic QuickSort (last-element pivot) recurses to depth N on sorted/reverse-sorted input, so N is capped at 5000 to stay safely within the browser's call stack.

Deterministic QuickSort always picks the last element as the pivot. On already-sorted or reverse-sorted input, every partition splits the array as unevenly as possible (one side empty), degrading to O(n²) comparisons and O(n) recursion depth.

Randomized QuickSort swaps a uniformly random element into the pivot position before partitioning. This makes the partition sizes balanced in expectation regardless of input order, giving expected O(n log n) performance on every input type — including the ones that break the deterministic version.

This is why production sort implementations (Python's Timsort, C++'s Introsort) use randomization or median-of-three pivot selection rather than a fixed pivot position.
